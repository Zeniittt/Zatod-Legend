CONFIRMED CRYSTAL LEGENDS FLOWS
Campaign: client simulates combat from a server seed and local/synced data. Manual skill intent is recorded by tick. On a winning ordinary stage, exit_stage includes claimed result, stars, Heroes and packed operations (_oprations on this client protocol). Checker stage logic recreates the battle and applies those operations.
Automatic Arena (ladder): start returns both teams, seed and bonuses. Its _result is request success/failure, not battle victory/defeat. Client enters Arena and simulates it; checker can independently simulate both teams. Exact backend scheduling before/during/after presentation is unknown.
Realtime PvP (real_pvp / KingsPvp / WCA): match/room flow uses TCP; combat inputs are synchronized over UDP with ACK/resend. Clients receive their own and opponent operations by tick, wait for server-provided tick data after startup, and catch up when behind. This is input/frame synchronization; continuous full server combat simulation and server late-input rules are not proven from available code.
Replay: showReplay seeds RNG, restores teams/operations and calls enterRelay to re-simulate. Replay mode exits before the new-battle settlement path.
Key scripts: battle/battle_engine.lua; battle/battle_tick.lua; battle/battle_check.lua; hello_server.lua; helloserver/job_handler.lua; network/network_udp.lua; ui_new/modules/kingsPvp/.
A replay checker tests whether submitted inputs produce a valid result. Final-log checking alone does not prove those inputs were the original human history; additional backend constraints are unknown.

HERO AND ITEM BALANCE REQUIREMENTS FROM THE ZATOD CHAT
Keep JSON .txt configs with an Editor, separate Stats/Items/Skills/Heroes files/tabs, and stable IDs. No change to ScriptableObject authoring was requested.
CharacterData.HeroDesk is List<HeroData>. Save progression and actual item IDs, not computed final stats. HeroData stores EquippedItems and AbsorbedItems; absorbed entries retain RankId, SlotId, ItemId and Quantity.
HeroStatCalculator currently sums BaseStats + rank bonuses + current-config stats of absorbed items + current-config stats of equipped items. Level/star growth are not yet part of that calculator.
User example: base 5 + one absorbed axe at 5 + two equipped axes at 5 = 20. Balance base to 3 and axe to 10 gives 33 on recalculation.
Changing axe stats affects existing references. Changing a rank recipe from axe to sword does not rewrite previously absorbed axes or equipped-item history. Converting existing items needs an explicit data migration; that policy was left for a concrete case.
Create detached HeroBattleData at battle entry. Stage buffs/debuffs modify runtime data, not saved progression or definitions.
Crystal runtime tables include Unit, UnitRank, hero_equip, equip, Skill and Buff plus Hero-specific hooks. Its stat path uses rank-table values and current equipment, not the same AbsorbedItems ledger. Do not blindly add imported rank totals and the same absorbed equipment twice. The original config-authoring/export tooling was not recovered.
